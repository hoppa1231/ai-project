# Выборочный VPN и сценарий Telegram

Задача: восемь пунктов пользователя — гостевой Telegram на дефолтном узле; полный интерфейс после Telegram; DIRECT по умолчанию; простое добавление сервиса/IP, отдельная кнопка приложений; базовая проверка доменных зон; оптимизация.

Изменения: Android MainActivity.kt, Screens.kt, data/BackendApi.kt, vpn/SingBoxConfigFactory.kt, AndroidManifest.xml. Новая гостевая политика с официальными Telegram CIDR; удалены переключатели общего VPN/DIRECT и действий правил; добавлено окно выбора launcher-приложений с загрузкой в IO; редактирование применяется только после серверного сохранения; убран двойной рестарт; индексы списка кешируются; смена сервера требует ротации. После Telegram входа очищается старый локальный конфиг, останавливается туннель, используются /nodes вместо inventory.

Backend: modules/policy/PolicyRoutes.kt проверяет Telegram, DIRECT, IDN/.ru/.su/.рф, блокирует legacy поля, catch-all /0 и пользовательские keyword/GEOIP. db/repo/PolicyRepository.kt создаёт DIRECT и выдаёт гостю только Telegram. modules/nodes/NodeRoutes.kt и modules/vpn/VpnRoutes.kt фиксируют гостю DEFAULT_VPN_NODE_ID и SINGLE; без настройки выдача запрещена. V13__selective_vpn.sql переводит старые политики и чистит несовместимые overrides, добавляет Telegram и базовый список сервисов. AppConfig.kt, backend/.env.example и docker-compose.yml — настройка дефолтного узла. docker-compose.prod.yml переключён на ./backend вместо старого root backend.

Проверки: make compose-validate и git diff --check прошли. make backend-test: скачивание Gradle 9.3.0 завершилось повреждённым zip/TLS handshake failure. make android-test: скачивание Gradle 8.7 завершилось read timeout. Попытки установленным Gradle 9.4.1 --offline: backend — отсутствует kotlin-stdlib 2.3.0; Android — отсутствует AGP 8.5.2. Новые DomainValidationTest.kt и изменения SingBoxConfigFactoryTest.kt не выполнены; компиляция/APK не подтверждены. Телефон, DNS, реальный VPN и Xray ограничения не проверялись. Compose production отдельно не проверялся.

Развёртывание/границы: docs/selective-vpn.md и docs/examples/telegram-only-xray-routing.json. Гостевой inbound должен быть отдельным и разрешать только Telegram IP + TCP DNS 1.1.1.1:53, остальное BLOCK. Код на удалённых узлах ничего не менял; без этих правил модифицированный клиент может обойти Android ограничения. Старые гостевые реквизиты на прежних inbound нужно отозвать отдельно. Quota сохранена. Базовый список не полный реестр блокировок. Нет измеренных CPU/RAM/батарея улучшений.
