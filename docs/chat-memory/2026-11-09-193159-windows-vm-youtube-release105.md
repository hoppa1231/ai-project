# Windows11 VM: TUN, YouTube, приложения и обновление 1.0.5

Задача: пользователь сообщил «VPN включён, но сайты/программы не работают», разрешил Windows-ВМ и отдельно попросил проверить YouTube. Telegram-вход тестового устройства подтверждён пользователем; секреты и конфиги с физического ПК не переносились.

## Среда и подтверждённые результаты

Изолированная KVM/QEMU Windows11 Enterprise Evaluation, NAT, 4CPU/6GiB. Существующий диск КОМПАС использован только backing-файлом; отдельный overlay/EFI/TPM в `desktop-client/build/windows-vm/`. Базовый диск не изменялся. QMP управлял только гостем. Каталог ВМ и результаты закрыты правами0700; содержат приватное состояние, не распространять. Это build-каталог: перед gradle clean обязательно остановить ВМ. Временный localhost bridge18771 обслуживал гостевые QA jobs.

Реально проверено на Windows:
- Обычный Install.exe 1.0.4, GUI без административных прав; автоматический UAC для chspch-tun-helper.exe; chspch0 Up, sing-box работает.
- Отключение освобождает TUN/core; повторное подключение в том же GUI использует тот же helper PID без второго UAC. Нормальный выход освобождает helper/core/адаптер.
- Авторизованный TUN через Францию: YouTube, myanimelist.net, example.com HTTP200. Системный ручной прокси выключен. Telegram200 проверен и в гостевом режиме.
- Edge с отдельным QA-профилем без ручного прокси действительно воспроизводил публичное YouTube-видео «Me at the zoo»: currentTime6.710718/19.021, paused=false, readyState4, error=null, frames363, buffered19.021 (`build/windows-vm/results/0026.txt`). Это проверка видео, не только HTML200.
- В списке программ Microsoft Edge представлен группой28EXE; выбор и применение сохранили28processPaths, TUN продолжил работу без нового UAC.
- Старая1.0.4 обнаружила опубликованную1.0.5: карточка и настоящий Windows toast. Кнопка приложения скачала полный публичный архив, размер/SHA256 совпали.
- Скачанный Install.exe1.0.5 завершился0, GUI запустился. Один основной JAR, его SHA совпал с JAR из опубликованного архива; accessToken и28выбранныхEXE сохранились. Полный hash session.json изменился из-за нормального отключения/отзыва runtime-конфига: это не признак потери входа.
- После обновления1.0.5 новый штатный UAC, YouTube и MyAnimeList снова200 через TUN; чистый установленный сканер нашёл36приложений/11групп с несколькимиEXE (`0035.txt`).

## Найденная ошибка и исправление

На1.0.4 чтение защищённой WindowsApps/MS Teams записи выбрасывало AccessDeniedException и обрывало весь список приложений. `desktop-client/src/main/kotlin/app/chspch/desktop/InstalledApps.kt`: недоступная запись изолирована через windowsEntry/runCatching, остальные программы сохраняются. Добавлена регрессионная проверка в InstalledAppsTest. 23JVM теста PASS, createDistributable/prepareWindowsJars PASS. Go installer tests предыдущего этапа PASS; установка поверх существующей версии теперь дополнительно проверена в реальной Windows.

Версия1.0.5 собрана и опубликована через `ops/desktop-updates/publish.py`; обновлены README и WINDOWS-CHECK.md. Публичный feed и архивы проверены publisher. ## Ограничения

Ошибка сканера не доказана причиной прежнего отказа сайтов пользователя. На физическом Windows-ПК пользователя/Windows10/его сети воспроизводимость ещё не проверена. Sleep/Wi-Fi/все сторонние приложения не проверены. В NAT-ВМ forcedIPv6 curl не работал также без VPN; один UI API timeout не воспроизведён отдельными JDK-запросами, причина не установлена. Спекулятивные DNS-изменения не вносились. Не объявлять все Windows-сценарии исправленными.

Следующий шаг: пользователю установить1.0.5, выбрать Францию и проверить YouTube/свои приложения на физическом ПК; при отказе нужны выбранный сервер, программа и видимая ошибка, без session/config файлов. Изменения не коммитились/не отправлялись в Git remote.
