# Доставка входа через Telegram

Когда Telegram не достигает публичного webhook API, relay на fra получает обновления через исходящий long polling и передаёт их в существующий backend webhook. Проверку challenge, связывание аккаунта и выдачу сессии выполняет backend, а не relay.

Служба `securevpn-telegram-relay.service`: код `/opt/securevpn-telegram-relay/relay.py`, закрытый root-only `/etc/securevpn-telegram-relay.env` с `TELEGRAM_BOT_TOKEN` и `LOGIN_WEBHOOK_URL`. Env не включать в Git. StateDirectory хранит только числовой offset, без сообщений и профилей. systemd запускает отдельного DynamicUser, рестартует при сбоях; исключения и payload не записываются в журнал.

При запуске relay вызывает deleteWebhook с drop_pending_updates=false, чтобы сохранить очередь. Backend TELEGRAM_WEBHOOK_SECRET должен оставаться настроенным: он защищает приёмник и отключает встроенный конкурирующий getUpdates worker. Должен работать только один relay для этого бота.

Offset подтверждается только после успешной передачи backend. На приватный /start от пользователя бот отвечает подсказкой вернуться в приложение; это подтверждение доставки команды, а не заявление об успешном завершении регистрации. Истёкший challenge нужно создать заново в приложении. При отказе backend доставка повторяется; отказ отправки подсказки не повторяет уже доставленный вход.

Проверки: `python3 -m unittest discover -s ops/telegram-login-relay -v`. Они не обращаются к Telegram. Live-проверку входа завершает пользователь нажатием «Старт» по свежему запросу из приложения.

Откат: остановить/отключить relay, затем восстановить HTTPS webhook штатным setWebhook с текущим секретом. Не запускать одновременно webhook и getUpdates и не сбрасывать очередь без явной необходимости.


Перенос 2026-11-09: fin достигает Telegram API, но не достигает backend по HTTPS/SSH; fra достигает обеих сторон. Служба на fin остановлена и отключена, служба на fra включена. При переносе сохранены root-only env и числовой offset; старую службу остановили до запуска новой. Наличие active в systemd не подтверждает доставку: проверять безопасные записи `Login update delivered` и свежий вход пользователя. Не запускать прежнюю службу одновременно с новой.
