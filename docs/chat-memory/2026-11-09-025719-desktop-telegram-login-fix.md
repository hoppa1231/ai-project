# Исправление входа Telegram в настольном прототипе

## Запрос и диагностика

При работающем ядре кнопка входа была недоступна (`!connected`). После обхода
отключением пользователь получал от бота подсказку для обычного /start, проверка
не завершалась. Клиент открывал только telegramWebUrl и подавлял ошибки открытия.
Код relay показывает: процитированная подсказка соответствует отсутствию payload.
По старым логам не установлено, на каком переходе терялся start-параметр.
На Linux зарегистрирован tg handler org.telegram.desktop.desktop.

## Изменения

- desktop-client/.../Main.kt: вход разрешён при работающем ядре; tg-ссылка
  открывается напрямую, web-вариант отдельной кнопкой; ошибки открытия видимы,
  инструкции требуют открывать бота по новой ссылке, а не отправлять обычный /start.
- TelegramLoginLinks.kt: проверяет схему, адрес бота и одинаковый auth challenge
  у обеих серверных ссылок. Telegram payload не удаляется при открытии.
- DesktopApi.kt: истёкшая ссылка имеет понятную ошибку. При READY новая сессия
  и старые реквизиты для отзыва сохраняются вместе. pendingRevocations хранит
  прежнюю гостевую сессию в закрытом файле; отзыв идёт с прежним access/refresh,
  при ошибке запись сохраняется для повторной попытки. Токены не печатаются.
- После READY GUI останавливает гостевое ядро, запрашивает отзыв, обновляет узлы;
  предлагает подключиться к обычному серверу. До READY прокси остаётся включён.
- README.md обновлён. Backend и relay в этой задаче не изменялись/не развёртывались.
