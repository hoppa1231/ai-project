# Обновления ЧСПЧ для ПК

Постоянная страница: https://tech-supp-test.ru/updates/desktop/
Windows: https://tech-supp-test.ru/updates/desktop/latest-windows-x64.zip
Linux: https://tech-supp-test.ru/updates/desktop/latest-linux-x64.tar.gz

Клиент начиная с1.0.4 проверяет latest.json при запуске и раз в6ч, пока запущен,
в том числе в трее. Уведомление ОС через поддерживаемый tray, постоянная карточка
в приложении и ручная проверка в настройках. Закрытый процесс уведомлять не может.
При недоступной сети тихая проверка повторится в следующий период; ручная покажет ошибку.

Кнопка Скачать загружает архив в приватный каталог updates профиля, проверяет
платформу/HTTPS origin/размер/SHA256, при ошибке удаляет частичную загрузку.
Установка остаётся явной: распаковать всю папку, закрыть прежний ЧСПЧ, Install.exe
на Windows или install-linux.sh на Linux. Профиль хранится отдельно и сохраняется.
Нельзя запускать Install.exe прямо из просмотра ZIP без полной распаковки.
Это уведомление/проверенная загрузка, не тихая фоновая установка.
Метаданные и архивы доступны без аккаунта и без VPN; VPN-реквизитов в них нет.
ОС Windows-подписи пока нет; доверие публикации опирается на HTTPS и хеш из feed.

Публикация новой версии: повысить DESKTOP_VERSION/packageVersion и имена упаковщиков,
затем из корня:

    python3 ops/desktop-updates/publish.py --notes "Описание изменений" --jre /tmp/chspch-windows-jre.zip

Скрипт собирает/тестирует приложения, Windows helper/launcher и оба архива; проверяет
размеры, загружает по SSH moscow в staging, сервер сверяет SHA256, публикует immutable
имена с хешем, заменяет stable symlinks и latest.json. Старый feed сохраняется в history,
понижение и подмена уже опубликованной версии запрещены. --skip-build только для
готовых артефактов; --dry-run готовит локальный manifest без публикации.

nginx location отдельно от Android/backend: /var/www/chspch-updates/desktop,
только GET/HEAD, без listing, no-store. configure.py добавляет include рядом с Android,
делает backup и nginx -t до reload с rollback при ошибке. Обычно повторять не нужно.
Проверка релиза: публичный feed, HEAD обоих архивов и реальная загрузка с SHA256
клиентом. На Windows также проверить системное уведомление и установку поверх версии.

Передача возобновляемая: staging UUID записывается в dist/desktop-updates/<version>/staging.json.
При обрыве повторить ту же команду с --skip-build --resume-stage <UUID> и теми же
notes/архивами. Скорость ограничена; уже переданные байты не отправляются заново.
Latest переключается только после проверки обоих архивов на сервере.
