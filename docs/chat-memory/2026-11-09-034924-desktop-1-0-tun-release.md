# ЧСПЧ Desktop 1.0 — оформление, системный TUN и пакеты

## Задача / подтверждения пользователя

Пользователь подтвердил вход с ПК и отправку/приём Telegram-сообщений через
локальный прокси, затем поручил довести приложения до итогового вида. На вопрос
о Windows ответил, что сможет проверить архив на настоящем ПК. Это согласие на
QA, а не подтверждение работоспособности Windows.

## Изменения

- Отдельный `desktop-client/` сохранён. Android/backend/relay не изменялись;
  существующие чужие незакоммиченные изменения сохранены, commit/push нет.
- Main.kt / PosterStyle.kt: перенесены настоящие шрифты, PNG рубильника,
  спидометра/стрелки/иконок и бордово-золотая палитра Android. Адаптивное окно,
  связь/серверы/маршруты/скорость/настройки. Окно реально открыто и осмотрено.
  Снимок: desktop-client/build/screenshots/desktop-home.png.
- DesktopController.kt: автоматическое подтверждение Telegram-входа, сохранение
  аккаунта, редактор серверных сайтов/IP, локальный process_path для программ,
  индикаторы HTTPS без блокировки кнопок, текущий/предыдущий успешные замеры,
  отмена замера, ограниченные переподключения и обработка паузы UI/сна.
- DesktopIntegration.kt: пользовательский автозапуск, ярлык меню; опциональный
  трей. По умолчанию X завершает приложение; при включённом поддерживаемом трее
  сворачивает. Автозапуск и автоподключение включаются отдельно пользователем.
- DesktopConfig.kt: DIRECT по умолчанию, TUN dns_mode=hijack, Linux auto_redirect,
  process_path, прямые исключения .ru/.su/.рф перед процессными правилами.
- ElevatedTunnel.kt / TunnelRuntime.kt: повышается только отдельный помощник,
  GUI работает от пользователя. Linux pkexec, Windows UAC через Start-Process.
  Случайный loopback rendezvous и256-битный секрет в приватном временном файле;
  токены/конфигурация не передаются в аргументах.
- helper/: Go, строгая проверка допустимых полей, закрепление проверенных байтов
  core по SHA256, копирование в закрытый каталог администратора перед exec,
  heartbeat2сек/lease12сек, штатная остановка. Linux parent-death signal;
  Windows CTRL_BREAK + Job Object kill-on-close. Нет постоянной root-службы или
  беспарольного polkit-правила. События ROUTED_VPN/DIRECT обезличены: только счётчики.
- DesktopApi.kt: pending-гость отзывается старой сессией; ошибка старого узла не
  блокирует отзыв текущего конфига. Неуспешные записи сохраняются для повтора.
- launcher/: обычные Windows Install.exe/Chspch.exe, без консоли и VBScript,
  установка в LOCALAPPDATA/Programs/Chspch, ярлыки «ЧСПЧ» рабочего стола/Пуска.
- scripts/: проверенные core/JRE, кросс-упаковка Windows с Temurin21.0.13+9,
  Linux portable/установщик. Обновление Linux исправлено на staged replace:
  простой cp упирался в read-only Java legal-файлы. Новая версия готовится отдельно,
  предыдущая хранится в chspch.previous; чужой каталог не перезаписывается.
- README.md, WINDOWS-CHECK.md, THIRD_PARTY.txt, лицензии шрифтов/Go/core включены.
  Workflow desktop.yml обновлён для Go/native image/MSI; не отправлялся/не запускался.

- Installer regression: свежая установка и2 обновления synthetic read-only Java,
  один откат, ярлык, отсутствие незавершённого stage — прошли. Реальное повторное
  обновление пользовательской установки тоже прошло.
- Linux установлен в /home/user/.local/share/chspch, ярлык в меню, существующий
  аккаунт сохранён, запущено именно установленное окно. Сопоставлены bin/helper/core

## Ограничения / следующий шаг

Windows EXE/JAR/core/helper кросс-собраны и структурно проверены; реального запуска,
UAC, драйвера, установки/обновления и сетевых маршрутов Windows здесь не было.
Пользователь согласился проверить: распаковать всю папку, Install.exe, подключение,
Telegram-вход и сообщения без ручного прокси, отключение. План WINDOWS-CHECK.md.
Пакет без цифровой подписи, автообновления и keyring/Credential Manager нет.
Физический сон/смена Wi-Fi, конкретные process_path-программы, замер скорости и
все страницы GUI отдельно сквозным тестом не подтверждены. Механизмы реализованы;
не приравнивать компиляцию к проверке этих сценариев. Зашифрованный DNS/SNI и
дочерние процессы могут влиять на выборочную маршрутизацию программ.
Нативный launcher по-прежнему пишет stderr pure virtual method called/terminate,
но GUI и packaged smoke продолжаются; источник сообщения отдельно не установлен.
