# Обновления Android ЧСПЧ

Один раз передать пользователю APK с механизмом обновлений (начиная с1.2). Затем клиент проверяет `https://tech-supp-test.ru/updates/android/latest.json` при открытии и через JobScheduler раз в6 часов, когда Android разрешает фоновую работу и есть сеть. При отключённых уведомлениях остаётся диалог в приложении и «Устав → Обновление приложения». Мгновенной push-доставки нет. После принудительной остановки приложения Android не запускает его фоновые задания до следующего открытия.

## Публикация одной командой

Из корня checkout:

```bash
python3 ops/android-updates/publish.py --version 1.3 --notes "Описание изменений для пользователя"
```

Команда повышает versionCode на1, записывает versionName, собирает debug APK и запускает JVM-тесты, проверяет пакет/ABI/подпись, передаёт сжатый APK по SSH alias `moscow`, проверяет его SHA-256 на сервере и атомарно заменяет latest.json. Рабочий backend и VPN-узлы не перезапускаются. Локальные копии релиза сохраняются в игнорируемом `dist/android-updates/<versionCode>/`.

По умолчанию публикуется ARM64. Для других уже поддерживаемых ABI повторить `--abi`:

```bash
python3 ops/android-updates/publish.py --version 1.4 --notes "Изменения" --abi arm64-v8a --abi armeabi-v7a
```

`--dry-run` собирает и проверяет релиз локально. `--skip-build` повторно публикует уже собранные APK после сбоя передачи; не сочетать с `--version`. Одинаковый versionCode нельзя публиковать с другим содержимым. Уже опубликованные APK имеют неизменяемые имена с хешем; предыдущие файлы сохраняются для клиентов, начавших загрузку раньше. Старый latest.json сохраняется в history; понижение versionCode запрещено. Исправление плохого релиза публикуется новым повышенным code.

Постоянная ссылка для первой установки ARM64: https://tech-supp-test.ru/updates/android/latest-arm64-v8a.apk — скрипт обновляет её атомарно вместе с выпуском. Дальнейшие обновления пользователь получает внутри приложения.

## Подпись и проверка

Используется существующий debug-сертификат прежних установок, чтобы не потерять совместимость обновлений. Его публичный SHA-256 закреплён в publish.py. **Не удалять и не пересоздавать текущий signing keystore**, не отправлять его пользователям, не записывать его пароль в Git. Перед переносом сборки на другой компьютер нужен безопасный перенос/резервная копия того же ключа. Новая production-подпись требует отдельного плана миграции и не подменяется автоматически.

Метаданные и APK открыты по HTTPS без авторизации и без VPN. В метаданных нет VPN-реквизитов. APK загружает системный DownloadManager. Перед установкой клиент проверяет размер, SHA-256, packageName, versionCode и совпадение сертификатов с установленным приложением. Завершение фоновой загрузки дополнительно проверяет отдельное устойчивое задание JobScheduler; экспортированный broadcast-приёмник не требуется. Скачанный файл копируется и проверяется во внутреннем cache; FileProvider открывает установщику только этот каталог. При ошибке проверок файл отбрасывается и доступен повтор загрузки. Android запрашивает разрешение на установку из ЧСПЧ и подтверждение установки. Вход/настройки обновляются поверх прежней установки без очистки данных. Приложение не выполняет тихую установку.

## Сервер

nginx snippet `nginx.conf` включён в HTTPS server tech-supp-test.ru. Публичный каталог `/var/www/chspch-updates/android`, загрузочный staging `/opt/securevpn-staging/android-updates`. Только GET/HEAD, без листинга, Cache-Control:no-store. Перед изменением nginx конфиг сохраняется; обязательны `nginx -t` и reload. Скрипт публикации предполагает, что этот каталог уже настроен и SSH-пользователь имеет право записи.

Ручные проверки: открыть latest.json без VPN/без Bearer; проверить HEAD APK; на старой версии получить предложение, скачать, разрешить установку, подтвердить Android, убедиться в повышении versionCode и сохранении авторизации. Сборка/тесты сами по себе не подтверждают установку или работу VPN.
