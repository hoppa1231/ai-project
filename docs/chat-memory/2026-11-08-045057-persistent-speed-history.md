# Сохранение истории замеров скорости

Поручение: запоминать предыдущие замеры и показывать в том же формате с отметкой предыдущего.

SpeedTestHistory.kt: локальный SharedPreferences speed_test_history, JSON completed_results, последние20 завершённых результатов (id, время, средняя/пиковая скорость, ping, объём). Пустые/нечисловые/повреждённые записи отбрасываются поштучно; ошибки и отмены измерения не сохраняются.

Screens.kt SpeedScreen: общий SpeedReadout используется текущим результатом и историей (тот же прибор, FlipNumber, метрики). После завершения новый результат сохраняется и не дублируется в предыдущих; при новом тесте прошлые видны ниже. После повторного открытия последний сохранённый результат отображается на основном приборе как ПРЕДЫДУЩИЙ ЗАМЕР с датой/временем, более старые доступны прокруткой LazyColumn. Формат значений сохранён.

Проверки: assembleDebug/testDebugUnitTest SUCCESS16s,14tests0failures (3 новых SpeedHistoryCodecTest: round-trip, повреждённая запись, невалидные результаты). APK установлен -r -t с сохранением данных. Пользователь разблокировал телефон. Выполнен один реальный успешный сетевой замер, запись подтверждена в SharedPreferences. После adb am force-stop и запуска приложения показана пометка ПРЕДЫДУЩИЙ ЗАМЕР; средняя скорость и ping совпали с сохранёнными, JSON не изменился. Визуально проверен /tmp/vpn-speed-restored.png. Измерения не подменялись синтетическими данными в приложении. Исходное stayon0 восстановлено. Diff-check passed, commit/push не выполнялись.

Ограничения: на устройстве проверено сохранение/восстановление одного результата;20элементов и длинная история на устройстве не заполнялись. VPN в этой задаче не проверялся. Сохранение локальное, серверной синхронизации нет.
