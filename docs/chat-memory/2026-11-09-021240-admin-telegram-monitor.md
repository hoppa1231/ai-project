# Админ-панель: мониторинг по Telegram

## Задача
Сделать backend-панель удобнее для мониторинга VPN-пользователей с привязкой к Telegram.

## Изменения
- `backend/src/main/kotlin/com/example/modules/admin/AdminRoutes.kt`: главный блок мониторинга в `/admin`, Telegram ID/имя/username со ссылкой, устройство/конфигурация, сервер, счётчики вверх/вниз, время снимка; поиск, фильтры, ручное и автоматическое обновление. Старые инструменты управления сохранены в раскрываемом блоке.
- POST `/admin/monitor/sync` защищён ADMIN JWT, опрашивает узлы и обновляет инвентарь. Ошибки отдельных узлов возвращаются по именам без текста исключений; прежние снимки сохраняются.
- Telegram-профиль берётся через владельца control-plane конфигурации; inventory Telegram ID используется как fallback. `UserRepository.telegramProfile` читает только поля профиля.
- Рост трафика сравнивается между снимками в браузере. Это признак активности, не точный online. Старше 2 минут — устаревшие данные. Первый замер не доказывает активность. Число Telegram-пользователей относится к представленным в инвентаре конфигурациям.
- При выходе очищаются таблицы мониторинга/клиентов/устройств и сохранённый токен.

## Ограничения и следующий шаг
Не развёрнуто, браузерная визуальная проверка и интеграция с живой БД/узлами не выполнялись. Это не подтверждение VPN-подключения. Следующий шаг — визуально проверить `/admin`, затем развернуть backend и проверить снимки реальных узлов. Синхронизация узлов последовательная, большие инвентари пока без пагинации; рост трафика хранится только между обновлениями текущей страницы.
