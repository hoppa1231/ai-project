# ЧСПЧ для Windows и Linux

Настольный клиент на Kotlin/Compose Desktop с оформлением Android-приложения:
бордово-золотая палитра, Playfair/PT Sans/Russo, исходный рубильник и спидометр.
Android-клиент и backend для этого переноса не изменялись.

## Готовые пакеты

`build/distributions/chspch-linux-x64-1.0.tar.gz`: распаковать всю папку `Chspch`,
запускать `bin/Chspch`. `install-linux.sh` устанавливает в пользовательский каталог
и создаёт пункт меню. Обновление готовит новую папку и заменяет её атомарно;
одна предыдущая версия сохраняется рядом в `chspch.previous` для отката.
Установка не требует root, Java уже включена.

`build/distributions/chspch-windows-x64-1.0.zip`: распаковать всю папку. `Install.exe`
копирует приложение в `%LOCALAPPDATA%/Programs/Chspch` и создаёт ярлыки рабочего стола и меню «Пуск».
`Chspch.exe` запускает переносную версию без установки и консольного окна.
Java21, Windows DLL Skiko, sing-box и помощник уже включены.
Windows-пакет кросс-собран на Linux; его запуск, UAC, сетевой драйвер и маршрутизация
должны быть проверены на настоящей Windows. Пользователь согласился выполнить QA.

## Подключение

По умолчанию используется системный TUN. Приложение показывает штатный запрос
polkit на Linux или UAC на Windows. Подтвердите его в системном окне.
Не запускайте весь GUI от root/администратора: повышенные права нужны помощнику.

Существующий принцип сохранён: `DIRECT` по умолчанию, выбранные сайты/IP/геонаборы
через VPN. Для распознанных доменов .ru/.su/.рф правило DIRECT стоит перед правилами программ.
Зашифрованные DNS/SNI и дочерние процессы требуют проверки конкретного приложения.
В разделе «Маршруты» можно добавлять сайты/IP, переключать и удалять свои правила.
Выбор исполняемых файлов программ хранится локально; используется `process_path`.
Android APP_PACKAGE не переносится в правила ПК. На Windows нужно выбирать
настоящий EXE, а не ярлык; на Linux — исполняемый файл процесса, а не скрипт запуска.
Работа конкретных программ зависит от их дочерних процессов и DNS; проверяйте
нужную программу после добавления. Правила применяются с переподключением.

Резервный режим — локальный HTTP/SOCKS5-прокси `127.0.0.1:17890`. В этом режиме
приложению, которое должно использовать прокси, надо задать этот адрес вручную.
При переходе на TUN удалите старый ручной прокси в Telegram/браузере, чтобы проверить
именно системный маршрут. Приложение не меняет чужие настройки прокси.

Гость подключает Telegram. Вход доступен при работающем VPN: кнопка открывает
прямую tg-ссылку с одноразовым кодом, есть резервная web-ссылка. Нажмите «Старт»
в открывшемся Telegram; клиент опрашивает подтверждение автоматически. Обычный
`/start` из старого чата не содержит код. Ссылка действует5мин. После входа гостевое
ядро останавливается, старый доступ отзывается старой сессией, загружаются обычные
серверы. При сбое отзыва закрытая запись сохраняется для повторной попытки.

## Поведение окна и сети

- Один экземпляр клиента на каталог данных.
- По умолчанию закрытие окна останавливает ядро и завершает приложение.
- Опция «сворачивать в трей» действует при поддержке системного трея. Меню значка
  позволяет открыть окно, подключить/отключить и выйти. В некоторых Linux-оболочках
  AWT tray может быть недоступен; тогда закрытие завершает клиент.
- Автозапуск создаёт только пользовательский desktop/startup-файл, без фонового
  подключения по умолчанию. Автоподключение включается отдельно.
- При потере процесса/помощника доступно до3 попыток восстановления. После паузы
  UI больше20сек включённое восстановление переподключает сеть (например, после
  сна). Изменение интерфейса обрабатывает `auto_detect_interface` sing-box.
  Физический сон и смена Wi-Fi отдельно не имитировались.
- Три индикатора раз10сек проверяют ya.ru, Google generate_204 и telegram.org;
  скрытое/свёрнутое окно проверки не запускает. 403/429 нейтральны.
- Скорость: реальный HTTPS-замер до speed.cloudflare.com, около12МБ, по текущим
  правилам. Это не обязательно скорость VPN-выхода: домен теста может идти DIRECT.
  Сохраняются только текущий и предыдущий успешные результаты, без дат в UI.
  Отмена и ошибки не записываются. Отмена доступна отдельной кнопкой.

## Помощник TUN

`helper/` — отдельный небольшой Go-процесс для Linux/Windows. Постоянная root-служба,
общий слушающий порт и правило polkit без пароля не устанавливаются. При каждом
повышении прав решение принимает ОС. GUI слушает случайный loopback-порт;
помощник подключается и подтверждает случайный256-битный секрет из закрытого файла.
Реквизиты VPN не передаются в аргументах процесса.

Помощник принимает только ограниченную конфигурацию ЧСПЧ, проверяя поля на каждом
уровне. Запрещены произвольные файловые rule-set/логи/кеши, сторонние слушатели,
другие типы outbound и непроверенные источники наборов. Принимается только
закреплённый по SHA256 sing-box. **Проверенные байты копируются в закрытый временный
каталог администратора и исполняются оттуда**, чтобы исключить подмену файла между
проверкой и запуском. Временная конфигурация удаляется после остановки.

Каждые2сек GUI посылает heartbeat. EOF/12сек без heartbeat останавливают ядро.
Linux использует SIGTERM и parent-death signal; Windows — CTRL_BREAK и Job Object
с kill-on-close. Через8сек зависший процесс принудительно завершается.
Штатное завершение даёт ядру убрать маршруты/DNS. Принудительная гибель самой ОС
не эквивалентна штатному отключению; состояние после неё требует проверки.

## Данные

Linux: `${XDG_CONFIG_HOME:-~/.config}/chspch/`, каталог0700, файлы сессии0600.
Windows: `%LOCALAPPDATA%/chspch/`, ACL профиля пользователя. В файле сессии находятся
токены и, при необходимости, старые реквизиты для повтора отзыва. Keyring/Credential
Manager пока не интегрирован. Не передавайте эти файлы другим людям.
Логи трафика, Telegram-профили, пароли и JSON VPN в репозиторий не записываются.
Автообновления/подпись Windows-пакета пока не реализованы; обновление — новым архивом.

## Сборка и проверки

Нужны JDK21, Go1.23+, Python3. При первой сборке нужен интернет.

```sh
python scripts/fetch-core.py linux-x64
# helper собирается автоматически при упаковке
bash ./gradlew test createDistributable
python scripts/package-linux.py
cd helper && go test ./...
```

Windows native image/MSI собирается на Windows через Gradle; для MSI нужен WiX3.
Есть workflow `.github/workflows/desktop.yml`; он не отправлялся и не запускался.
Кросс-упаковка переносного архива:

```sh
python scripts/fetch-core.py windows-x64
python scripts/build-helper.py windows-x64
python scripts/build-launcher.py
bash ./gradlew prepareWindowsJars
python scripts/package-windows.py
```

JRE Windows21.0.13+9 скачивается из официального Eclipse Temurin и проверяется по
закреплённому SHA256. VPN-ядро1.14.4 обеих ОС проверяется по digest официального
релиза. В пакетах есть upstream LICENSE и лицензии Google Fonts.

Opt-in live проверки, создающие отдельную гостевую сессию и отзывающие её:

```sh
CHSPCH_SING_BOX="$PWD/packaging/linux-x64/core/sing-box" bash ./gradlew smoke
CHSPCH_SMOKE_TUN=1 CHSPCH_SMOKE_NODE=Франция CHSPCH_SING_BOX="$PWD/packaging/linux-x64/core/sing-box" bash ./gradlew smoke
# Linux: аварийный exit JVM, уборка интерфейса/маршрутов и внешний отзыв сессии
python scripts/test-tun-lifecycle.py
```

Проверено на Linux: TUN создан, Telegram через системный маршрут HTTP200, обычный
сайт с DIRECT HTTP200, штатная остановка, уборка после аварийного выхода JVM,
интернет после cleanup HTTP200 и серверный отзыв всех тестовых конфигураций.
Проверка JSON/юнит-тесты сами по себе не доказывают работу VPN.

Авторизованный opt-in smoke (только при закрытом GUI): `CHSPCH_ACCOUNT_SMOKE=1 bash
./gradlew accountSmoke`. Использует сохранённый аккаунт, временное правило
проверки выхода только в памяти, затем отзывает конфигурацию. Не выводит IP/токены.
На текущем Linux подтверждены события реального VPN-outbound и выход выбранного
обычного сервера. Сравнение с исходным IP само по себе здесь не различает маршруты:
до запуска TUN он уже совпадал с адресом этого сервера; причина отдельно не установлена.

### Desktop 1.0.1: правила

На вкладке «Маршруты» список обновляется при открытии; кнопка «Обновить»
загружает изменения с других устройств. «Состав» открывает полный список
с поиском и копированием. После изменения правил на другом устройстве
нажмите «Применить к туннелю» или переподключитесь. Добавленный сайт
очищается из поля только после успешного сохранения, ошибки видны внизу окна.

Проверка myanimelist.net существующим аккаунтом (закройте GUI):
`CHSPCH_WEBSITE_SMOKE=1 ./gradlew websiteSmoke`. Проверяет системный TUN,
при отсутствии сохраняет явно запрошенное правило myanimelist.net; в конце
останавливает туннель и отзывает выданный конфиг. Не выводит реквизиты аккаунта.

### Desktop 1.0.2: выбор приложений

«Маршруты → Выбрать приложения» открывает список установленных программ:
поиск, несколько отметок, фильтр выбранных, обновление списка, единое применение.
Названия и выбор сохраняются локально; отмена ничего не меняет. Сетевые правила
программ действуют в TUN; активный туннель переподключается после применения.
Linux: XDG Desktop Entry меню пользователя/системы, с приоритетом пользовательских
записей и разрешением Exec через PATH/символические ссылки. Windows: ярлыки
Пуска/рабочего стола и реестр App Paths, без обхода всего диска или запуска программ.
Программы за общими интерпретаторами/Flatpak/Snap не выбираются как общий launcher;
portable и отсутствующие записи добавляются через второстепенное «Указать файл».
Дочерние процессы могут иметь отдельные исполняемые файлы и требуют отдельных правил.
Windows-сканер собран, но без реального Windows-сеанса runtime не подтверждён.

### Desktop 1.0.3: несколько EXE, векторный рубильник, права

Windows-приложение может содержать несколько процессов. Сканер находит EXE
в папке программы (до2 уровней подпапок, максимум300 файлов), исключая
типовые установщики/обновляторы/удаление. Отметка программы выбирает найденную
группу; «Файлы» позволяет выбрать отдельные EXE. Это эвристика, не полный
перечень всех возможных дочерних процессов. Общие системные каталоги не группируются.
Рубильник заменён масштабируемым Compose Canvas с текстовыми подписями.

При первом подключении TUN в текущем запуске GUI ЧСПЧ сам вызывает UAC в Windows
или pkexec в Linux. Помощник сохраняет авторизацию для переподключения/смены
правил; при отключении ядро и интерфейс останавливаются, помощник остаётся
ожидать. Выход из GUI завершает и помощник. Пароль не хранится, постоянная
служба/отключение UAC не устанавливаются. EOF/12s потеря heartbeat завершают
помощник с очисткой сети; после такого завершения потребуется новый системный
запрос. Отмена запроса останавливает автоматические повторы подключения.

Live Linux проверка: myanimelist.net200, stop/start200, запуск авторизованного
помощника ровно1. Windows собран, реальный UAC/многопроцессное приложение
на Windows требуют проверки на устройстве.

### Desktop 1.0.4: уведомления об обновлении

Проверка при запуске/раз в6 часов, пока клиент открыт или свёрнут в трей. Системное
уведомление при поддержке tray и карточка с кнопкой Скачать; ручная проверка
в настройках. Загрузка проверяет платформу/HTTPS origin/размер/SHA256. Архив
сохраняется в приватном updates каталоге профиля; далее полная распаковка и
установка поверх существующей версии после закрытия ЧСПЧ. Тихой установки нет.
Постоянная страница и ссылки: https://tech-supp-test.ru/updates/desktop/
Публикация следующего релиза: ../ops/desktop-updates/README.md. Для версий до1.0.4
требуется однократная установка клиента с механизмом проверки обновлений.

### Desktop 1.0.5: проверка в Windows-ВМ

Исправлен воспроизведённый отказ сканера: защищённая запись WindowsApps больше
не прерывает весь список. Проверено в Windows11 Enterprise:36 приложений,
11 групп с несколькими EXE. В отдельной KVM-копии выполнены обычная установка,
повторная установка с сохранением профиля и одним rollback, UAC только помощнику,
создание/очистка chspch0, повторное подключение без второго UAC. После штатного
Telegram-входа YouTube и MyAnimeList200; Edge без системного/ручного прокси
воспроизвёл видео YouTube с ростом currentTime и decodedFrames. Это проверка
конкретной Windows11-ВМ и сети; Windows10/физический ПК могут отличаться.
