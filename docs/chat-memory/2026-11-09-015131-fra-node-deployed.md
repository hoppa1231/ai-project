# fra добавлена как обычная VPN-нода

Задача пользователя: «добавь ноду к впн сервису ssh fra». Пользователь настроил временный sudo для max и отдельно разрешил одну отключённую служебную запись в inbound. Дефолтный ned не менялся.

На fra (Ubuntu 24.04) установлен Docker из системного apt. Созданы отдельные securevpn-panel и securevpn-node-agent, host network, restart unless-stopped, ограничение логов 10m × 3. Перенесены только фиксированные runtime-образы fin: panel d04315495d5332990e2793c66429da91f5f61b47483891df4ea52c5c4dbee9d6 и agent 25e477c5629fcf1111def34ec32c0b34fe5cfcc446e962df7f13261a4045b93e; существующие базы, пользователи и приватные ключи fin не копировались. Созданы новые REALITY-ключи и пароль панели на fra. Страна внешнего IP проверена через ipinfo: FR.

Конфигурация root-only /opt/securevpn-node, панель 127.0.0.1:9229, обычный VLESS REALITY inbound fra-exit на447, site koel.dev. Гостевой вход не создавался. Агент9090 разрешён только loopback и backend; стандартный порт подписок2096 разрешён только loopback. Правила /opt/securevpn-node/firewall.nft применяются отдельным enabled securevpn-firewall.service, Docker enabled. Чужие fail2ban/iptables правила сохранены. Проверено извне:447 reachable;9090/2096/9229 blocked or closed. Панель слушает9229 только loopback.

Первый перенос через локальный компьютер был медленным. Выполнен прямой fin→fra с временным SSH-ключом: from=IP fra, restrict, единственная forced command экспорта двух образов. Host key fin проверен по известному ключу. По завершении ровно одна временная строка authorized_keys удалена с fin; ключи удалены с fra. Остальные SSH-доступы не менялись.

На moscow штатный /auth/login с уже настроенными административными реквизитами, без ручного JWT. До регистрации резервная копия БД /opt/securevpn-staging/before-fra.dump и список nodes-before-fra.json. Скрипт /opt/securevpn-staging/check-register-fra.py, публичные метаданные fra-public-metadata.json, итог fra-node-state.json. Добавлена «Франция», country FR, region France, weight100, nodeRole EXIT, inboundTag fra-exit, ID34aa3865-2d70-4884-8e4d-f2b7435b8040. Через admin API подтверждены ACTIVE/HEALTHY. DEFAULT_VPN_NODE_ID по-прежнему совпадает с ned-guest. Backend health status/db ok,7total; число healthy динамическое и не является проверкой всех остальных нод.

Реальные сетевые проверки с moscow через отдельный Xray SOCKS-клиент: telegram.org HTTP200, example.com HTTP200, api.ipify.org вернул IP fra. После удаления тестового клиента: API инвентаря подтверждает отсутствие записи, новое соединение с прежними реквизитами отклонено.
